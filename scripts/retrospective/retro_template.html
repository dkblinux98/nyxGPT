Acceptance-perspective classification. The 168 issues labeled Acceptance Failure (defects found at stakeholder acceptance, before release) are classified by root cause: escaped defect — broken behavior in code that had passed review (a review miss); spec gap — the delivered work matched the issue but the requirement itself was wrong or incomplete (redesigns, consolidations, UX corrections); workflow miss — the agent pipeline itself failed (review gate, branch hygiene, submission workflows). Classification is keyword-heuristic over titles and bodies, hand-reviewed. No issue carries a Production Defect label.

Sprints. Sprint buckets are the Project's real Sprint iterations, read from the snapshot committed by the "Retro Dashboard - Dump Project Fields" workflow (scripts/retrospective/data/project_fields.json) — each issue lands in the sprint it was actually assigned to on the board, and Module values come from the Project's Module field. If the snapshot is missing, the builder falls back to calendar weeks bucketed by creation date and title-inferred modules (the sprint-axis caption says which mode is active). The last-7-days section always uses title-inferred modules. Milestones are the repo's phase milestones, ordered. The six issues under the "Phase X: Rejected" milestone (rejected, never worked) are excluded throughout.

Review gate. Monthly counts of PRs with ≥1 REQUEST_CHANGES come from the complete GitHub notification-email archive (thread-level, so a PR rejected in two months counts in both); merged-PR counts from the GitHub API. Feb shows more rejected than merged because rejected PRs often merged in a later month or were superseded.

Last 7 days. The 61 REQUEST_CHANGES reviews on nyxGPT PRs between 2026-07-26 and 2026-08-01, parsed from the structured review comments (Critical / Medium / Minor findings sections). Re-review rejections with no new findings count as a round with zero findings. Of 110 PRs merged in the window, 31 owner-carried workflow merges bypassed agent review and are excluded from first-pass stats; of the 79 reviewed PRs, 42 were approved first-pass — verified against each PR's review history. Module attribution follows the repo's module taxonomy, inferred from issue titles (the Project's Module field is not API-readable here). PR #3398 has no linked issue and is listed under its PR number.
